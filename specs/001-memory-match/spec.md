# Feature Specification: 神経衰弱（2人対戦・CPU対戦）

**Feature Branch**: `001-memory-match`

**Created**: 2026-11-24

**Status**: Draft

**Input**: User description: "神経衰弱（メモリーマッチ）Unityゲーム。2人対戦（各プレイヤーは人間/CPU弱・普通・強）、24枚(6x4,12ペア)、成立なら手番継続・外れなら交代、取得ペア数で勝敗、シード再現、矢印+Space+R操作、外れ時1.0秒表示後に裏へ。"

決定の根拠は `interview.md`、入力要件は `requirements-input.md` を参照。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 2人でペアを取り合って勝敗を決める (Priority: P1)

プレイヤー2人が交代でカードを2枚ずつめくり、同じ絵柄をそろえてペアを取得する。全ペアが取られた時点で、取得ペア数の多いほうが勝つ。

**Why this priority**: 「ペアでカードを取得できる」「二人以上で対戦できる」という必須ルールそのもの。これだけで遊べる最小のゲームになる。

**Independent Test**: 2人とも人間にしてシードを固定し、決まった順にカードをめくって手番・取得数・勝敗の表示が期待どおりになることを確認する。

**Acceptance Scenarios**:

1. **Given** ゲーム開始直後（M1）, **When** 盤面を見る, **Then** 24枚（6列×4行、12ペア）がすべて裏向きで、各絵柄がちょうど2枚ずつあり、両プレイヤーの取得ペアは0、残りペアは12、手番はプレイヤー1である。勝敗表示は出ていない。
2. **Given** 手番のプレイヤーがカーソルを持っている, **When** 矢印キーで移動しSpaceを押す（M2）, **Then** カーソル位置の裏向きカードが1枚表になる。1手番で表にできるのは2枚までで、2枚が表のあいだは3枚目をめくれない。
3. **Given** 手番のプレイヤーが2枚めくった, **When** 2枚が同じ絵柄（M3）, **Then** そのペアは手番のプレイヤーの取得となり、表のまま残る。取得ペアが1増え、残りペアが1減り、手番は同じプレイヤーのまま続く。
4. **Given** 手番のプレイヤーが2枚めくった, **When** 2枚が違う絵柄（M3）, **Then** 2枚は1.0秒表向きのまま見え、その後両方が裏に戻り、手番が相手に移る。取得ペアは変わらない。
5. **Given** 12ペアのうち最後の1ペアが取得された（M5）, **When** 取得が確定する, **Then** 取得ペアが多いプレイヤーの勝ちが表示される。同数なら引き分けが表示される。以後は盤面の入力を受け付けない。

---

### User Story 2 - CPUと対戦する (Priority: P1)

各プレイヤーを「人間」「CPU弱」「CPU普通」「CPU強」から選べる。CPUの手番では、CPUが自動でカードをめくる。人間1人対CPU、CPU同士、人間2人のいずれでも遊べる。

**Why this priority**: 「CPU戦を含む」が必須要件のため。

**Independent Test**: プレイヤー2をCPUにし、シードを固定して、CPUの手番が人間の操作なしに2枚めくりまで進むことを確認する。

**Acceptance Scenarios**:

1. **Given** 開始前の設定画面, **When** 各プレイヤーの種別を選んで開始する, **Then** 既定はプレイヤー1が人間、プレイヤー2がCPU普通で、選んだ組み合わせでゲームが始まる。
2. **Given** CPUの手番, **When** 手番が始まる, **Then** 人間の入力なしで、約0.8秒間隔で1枚ずつ、計2枚をめくる。判定・手番の扱いは人間と同じ規則に従う。
3. **Given** CPUの手番, **When** 人間がSpaceや矢印キーを押す, **Then** その入力は盤面に影響しない。
4. **Given** CPUが強度に応じた確率で見たカードを覚えている, **When** 覚えている絵柄の片方が表になっている, **Then** 覚えていれば残りの片方を狙い、覚えていなければ未確認のカードからめくる。覚えている確率は、弱25%、普通60%、強100%である。
5. **Given** 同じシードと同じ強度, **When** 同じ操作で2回プレイする, **Then** カード配置とCPUの選択がどちらも同じになる。
6. **Given** CPUが同じ絵柄の2枚を覚えている, **When** その手番が始まる, **Then** CPUは1枚目と2枚目でその2枚を選び、ペアを取得する。

---

### User Story 3 - 誤操作を防ぎ、最初からやり直せる (Priority: P2)

取得済み・表向きのカード、同じカードの二重選択はできない。途中でも終了後でも、Rで配置を作り直して最初の状態に戻せる。

**Why this priority**: 遊びの正しさ（M4）と繰り返しプレイ（M6）のため。P1 の後でも単独で検証できる。

**Independent Test**: 取得済みカードと表向きカードにカーソルを合わせてSpaceを押し、状態が変わらないことを確認する。Rを押して初期状態に戻ることを確認する。

**Acceptance Scenarios**:

1. **Given** 取得済みのカード、または今の手番で表になっているカード（M4）, **When** そのカードでSpaceを押す, **Then** 何も起きない。同じカードを2枚目として選べない。
2. **Given** 外れた2枚が1.0秒表示されている間, **When** Spaceを押す, **Then** 入力は受け付けられない。
3. **Given** ゲームの途中、またはゲーム終了後（M6）, **When** Rを押す, **Then** 配置がシャッフルし直され、全カードが裏向き、取得ペアは両者0、残りは12、手番はプレイヤー1に戻る。プレイヤーの種別設定とシードの扱いは開始時のとおりである。
4. **Given** シードを指定せずに開始した, **When** Rで再開する, **Then** 配置は前回と異なりうる。シードを指定している場合は、Rで再開しても同じ配置から始まる。

---

### User Story 4 - 制限時間つきで遊ぶ (Priority: P2)

ゲーム全体に制限時間（既定180秒）があり、残り時間が画面に表示される。時間内に全ペアが取られなければ、時間切れで終了し、その時点の取得ペア数で勝敗を決める。

**Why this priority**: 後半で追加する1機能。ゲームに緊張感を与える。既存のM5（終了）とM6（再開）に影響するため、それらも合わせて確認する。

**Independent Test**: シード固定で開始し、残り時間が減ることを確認する。時間切れ後に入力を受け付けないこと、Rで残り時間が戻ることを確認する。

**Acceptance Scenarios**:

1. **Given** ゲーム開始直後（A1）, **When** 盤面を見る, **Then** 残り時間が 180秒（3:00）と表示され、プレイ中は時間とともに減っていく。設定画面と、終了後は減らない。
2. **Given** 残り時間が0になった（A2）, **When** 全ペアはまだ取得されていない, **Then** 時間切れで終了し、その時点の取得ペア数が多いプレイヤーの勝ち（同数は引き分け）と、時間切れであることが表示される。以後はカードをめくれない。
3. **Given** 時間内に最後のペアが取得された（A3）, **When** 取得が確定する, **Then** 通常の終了（M5）になり、残り時間はそのまま止まり、減らない。
4. **Given** プレイ中、時間切れ後、または通常終了後（A4）, **When** Rを押す, **Then** 配置のシャッフルとともに、残り時間も180秒に戻る。
5. **Given** 時間切れの瞬間に、1枚だけ表になっている、または外れた2枚を表示中（A5）, **When** 時間が0になる, **Then** 取得済みでない表向きのカードはすべて裏に戻り、手番の交代は行わず、終了する。

---

### User Story 5 - マウスで操作する (Priority: P3)

キーボードに加えて、マウスでもカードの選択とめくり、設定画面の操作ができる。キーボードの操作は、これまでどおり使える。

**Why this priority**: 操作のしやすさの向上。ゲームのルール（M1〜M6、A1〜A5）は変えない。

**Independent Test**: マウスカーソルをカードの上に動かして選択枠が移ること、左クリックでめくれること、設定画面をクリックで操作して開始できることを確認する。

**Acceptance Scenarios**:

1. **Given** プレイ中, **When** マウスカーソルをカードの上に動かす, **Then** 選択枠（カーソル）がそのカードに移る。
2. **Given** 人間の手番で、マウスカーソルが裏向きのカードの上にある, **When** 左クリックする, **Then** そのカードが1枚めくれる（Space と同じ）。
3. **Given** 取得済みのカード、表向きのカード、外れ表示中、CPUの手番、または終了後, **When** クリックする, **Then** 何も起きない（M2、M4、M5 と同じ規則）。
4. **Given** 設定画面, **When** プレイヤーの行をクリックする, **Then** 左クリックで種別が次へ、右クリックで前へ切り替わる。
5. **Given** 設定画面, **When** 「START」をクリックする, **Then** その設定でゲームが始まる。
6. **Given** マウスを使ったあと, **When** 矢印キー、Space、Enter、R を押す, **Then** これまでどおり動く。マウスとキーボードは混ぜて使える。

---

### Edge Cases

- 外れた2枚の表示中（1.0秒）にRを押した場合は、再開を優先して初期状態に戻る。
- 最後のペアを取得した直後は、手番は続かず、終了画面になる。
- 2枚目をめくった時点で成立と判定されるため、成立ペアは1.0秒待たずに取得扱いになる。
- 12ペアが6対6に分かれた場合は、引き分けを表示する。
- CPU同士の対戦でも、最後まで人間の入力なしで終了する。
- カーソルが盤面の端にあるとき、さらに外へ移動しようとしても盤面外に出ない。
- 時間切れと最後のペア取得が同じタイミングになった場合は、ペア取得を優先し、通常の終了とする。
- 時間切れの時点で取得ペアが同数なら、引き分けを表示する。
- 外れた2枚の表示中（1.0秒）にも、残り時間は減る。
- マウスカーソルがどのカードの上にもないときは、選択枠は最後にいた位置に残る。
- 終了後の再開は R キーのみとする（マウス用の再開ボタンは作らない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、24枚のカードを6列×4行に並べ、12種類の絵柄をそれぞれちょうど2枚ずつ割り当てなければならない。
- **FR-002**: システムは、開始時とR再開時に、配置をシャッフルしなければならない。シードが指定されている場合は、同じシードから同じ配置を再現しなければならない。
- **FR-003**: システムは、開始時とR再開時に、全カードを裏向き、各プレイヤーの取得ペアを0、手番をプレイヤー1、残り時間を制限時間（既定180秒）にしなければならない。
- **FR-004**: 手番のプレイヤーは、矢印キーでカーソルを動かし、Spaceで裏向きカードを1枚めくれなければならない。
- **FR-005**: システムは、1手番でめくれるカードを2枚までに制限しなければならない。
- **FR-006**: システムは、取得済みのカード、表向きのカード、すでに今回選んだカードを選べないようにしなければならない。
- **FR-007**: システムは、2枚目がめくられた時点で絵柄を比較し、同じなら成立、違えば不成立と判定しなければならない。
- **FR-008**: 成立した場合、システムは2枚を手番プレイヤーの取得とし、表向きのまま残し、手番を同じプレイヤーに続けなければならない。
- **FR-009**: 不成立の場合、システムは2枚を1.0秒表向きで見せ、その後両方を裏向きに戻し、手番を相手に移さなければならない。表示中は盤面入力を受け付けてはならない。
- **FR-010**: システムは、各プレイヤーの取得ペア数と残りペア数、現在の手番、残り時間（分:秒）を常に表示しなければならない。
- **FR-011**: システムは、全ペアが取得された時点、または時間切れ（FR-020）の時点で、取得ペアが多いプレイヤーの勝ち、同数なら引き分けを表示し、以後の盤面入力を受け付けてはならない。
- **FR-012**: 開始前に、各プレイヤーの種別を「人間」「CPU弱」「CPU普通」「CPU強」から選べなければならない。既定はプレイヤー1が人間、プレイヤー2がCPU普通である。
- **FR-013**: CPUの手番では、システムは人間の入力なしで、約0.8秒間隔で1枚ずつ2枚をめくらなければならない。CPUの手番中の人間の盤面入力は無視しなければならない。
- **FR-014**: CPUは、すでに表になったことがあるカードの位置を、強度ごとの確率（弱25%、普通60%、強100%）で覚えていなければならない。覚えている同じ絵柄の2枚があれば、1枚目からその片方を選び、2枚目で残りの片方を選ぶ。1枚目が表になっていて、同じ絵柄の片方を覚えていれば、2枚目でそれを選ぶ。どちらでもなければ、まだ見ていないカードから選ぶ。
- **FR-015**: シードを指定した場合、システムはカード配置とCPUの選択を同じにして再現しなければならない。
- **FR-016**: Rは、ゲーム中でも終了後でも、FR-003の初期状態に戻さなければならない。表示だけでなく、取得数・手番・配置・CPUの記憶・残り時間を実際に初期化すること。シードを指定している場合は、CPUの乱数も開始時の状態に戻す。
- **FR-017**: すべての状態（各カードの表裏と取得者、各プレイヤーの取得ペア数、残りペア数、手番、残り時間、勝敗、終了の理由）は、外部から取得して確認できなければならない。
- **FR-018**: 絵柄は、色と記号で区別できなければならない。外部アセットは使わない。
- **FR-019**: システムは、ゲーム全体に制限時間（既定180秒）を持ち、プレイ中（外れ表示中を含む）は残り時間を実時間で減らさなければならない。設定画面、終了後は減らしてはならない。
- **FR-020**: 残り時間が0になった時点で全ペアが取得されていなければ、システムは時間切れで終了しなければならない。勝敗は取得ペア数で決め（FR-011）、終了の理由が時間切れであることを表示する。
- **FR-021**: 時間切れの時点で、取得済みでない表向きのカードは裏に戻し、手番の交代は行わず、以後の盤面入力を受け付けてはならない。
- **FR-022**: 全ペアが取得されたときは、残り時間の減少を止め、通常の終了とする。時間切れと最後のペア取得が同時になった場合は、ペア取得を優先する。
- **FR-023**: 制限時間は、CPUの手番にも同じように適用されなければならない（CPUに有利・不利な扱いをしない）。
- **FR-024**: マウスカーソルがカードの上にあるとき、選択枠はそのカードに移らなければならない。
- **FR-025**: 左クリックは、カーソル位置のカードに対する Space と同じ動作でなければならない。取得済み、表向き、外れ表示中、CPUの手番、終了後は何も起きない（FR-005、FR-006、FR-009、FR-013、FR-011）。
- **FR-026**: 設定画面では、プレイヤーの行の左クリックで種別を次へ、右クリックで前へ切り替え、「START」のクリックで開始できなければならない（FR-012）。
- **FR-027**: マウス操作の追加によって、キーボードの操作（矢印、Space、Enter、R）を変えてはならない。

### Key Entities

- **カード**: 絵柄、盤面上の位置、状態（裏向き／表向き／取得済み）、取得したプレイヤーを持つ。
- **プレイヤー**: 種別（人間／CPU弱／CPU普通／CPU強）、取得ペア数を持つ。
- **ゲーム**: 24枚のカード、2人のプレイヤー、手番、残りペア数、進行状態（設定中／プレイ中／終了）、シード、残り時間、終了の理由（全ペア取得／時間切れ）を持つ。
- **CPUの記憶**: CPUが見たカードの絵柄と位置、覚えている確率を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 人間2人で、シード固定の決まっためくり順を実行すると、手番・取得ペア数・勝敗の表示が受け入れシナリオ（US1）と100%一致する。
- **SC-002**: 同じシード・同じ設定で2回プレイすると、24枚の配置とCPUの選択が100%一致する。
- **SC-003**: CPU同士の対戦が、人間の入力なしで最後まで進み、勝敗または引き分けが表示される。
- **SC-004**: 強度ごとのCPUの記憶確率が、固定シードで多数回（1,000手以上）試行したとき、弱25%・普通60%・強100%に対して±5ポイント以内である。
- **SC-005**: M1〜M6に相当する受け入れ条件（US1〜US3）のすべてについて、操作・期待・実際・根拠が記録された verification.md が作られ、未成立が0件である。
- **SC-006**: R再開後に、取得数・手番・配置・カードの表裏がすべて初期状態に戻ることを、再開の前後で取得した状態で確認できる。
- **SC-008**: 時間切れまで操作せずに待つと、制限時間（180秒）の±2秒以内に時間切れで終了し、取得ペア数に応じた勝敗が表示される。
- **SC-009**: 時間切れの前後で、取得済みでないカードがすべて裏に戻り、以後の入力でカードの状態が変わらないことを、状態の取得で確認できる。
- **SC-011**: マウスだけで、設定から開始、全ペア取得の終了までを遊べる。
- **SC-012**: マウスの追加後も、M1〜M6 と A1〜A5 に相当する既存の受け入れ条件がすべて成立する（回帰確認）。
- **SC-010**: M1〜M6に相当する既存の受け入れ条件が、制限時間の追加後もすべて成立する（回帰確認）。
- **SC-007**: 初めて遊ぶ人が、説明なしで画面表示だけを見て、現在の手番と各自の取得数を判別できる。

## Assumptions

- 同じキーボードで人間2人が交代して操作する。同時操作は対象外である。
- 1ゲームは12ペア・2人で、3人以上、ほかの枚数、ほかの盤面は対象外である。
- スライドの「ミス上限」「スコア加減点」「ゲームオーバー」は対戦では使わない（Q4）。取得ペア数のみで勝敗を決める。
- 範囲外：効果音、オンライン対戦、ランキング、外部アセット、実行ファイルのビルド。
- 実装上の構造（クラス構成、シャッフルやCPUの実装方法、カードの見た目）はPlan工程で決める。
- 後半で追加する1機能は「制限時間」（User Story 4）。コンボ、枚数増加は対象外のままとする。
- マウス操作は、カード、設定画面の行、STARTに限る。再開（R）と制限時間の変更は、マウスでは行わない。
- 制限時間は既定180秒で、設定画面では変更しない（Play前にCLIから変える設定値とする）。
- 時間切れの勝敗は、通常終了と同じ規則（取得ペア数）で決める。時間切れ専用の得点・ペナルティは設けない。
